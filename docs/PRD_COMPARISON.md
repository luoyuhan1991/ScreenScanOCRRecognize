# 第一部分：主版本 PRD

## 1. 产品定位

**产品名称**：屏幕扫描OCR识别系统（主版本）

**核心价值**：在游戏匹配等待期间，定时截取屏幕（或指定区域），通过 OCR 识别屏幕文字，自动与预设关键词列表匹配，命中时以浮窗+音效形式实时提醒用户。

**目标用户**：需要在游戏匹配过程中快速识别特定玩家（如黑名单用户）的玩家。

## 2. 功能清单

### 2.1 核心功能

| 编号 | 功能 | 描述 |
|------|------|------|
| F1 | 定时屏幕截图 | 按可配置间隔（1-15秒）自动截取全屏或 ROI 区域，使用 mss 高性能截图（PIL 作为 fallback） |
| F2 | OCR 文字识别 | 支持 PaddleOCR 和 EasyOCR 双引擎，支持中文/英文，可配置最低置信度阈值 |
| F3 | 关键词匹配 | 从关键词文件加载匹配列表，支持子串匹配和模糊比例匹配（阈值可调 50%-100%） |
| F4 | 浮窗提醒 | 匹配命中时在屏幕显示半透明浮窗，双栏布局：左侧累积匹配历史 + 右侧当前 OCR 结果 |
| F5 | 音效提醒 | 匹配到新关键词时播放提示音（1000Hz 蜂鸣，200ms），同一关键词每会话仅提醒一次 |

### 2.2 性能优化功能

| 编号 | 功能 | 描述 |
|------|------|------|
| P1 | 帧差检测 | 将截图缩放为 160x120 灰度图计算 MSE，画面无变化时跳过 OCR 直接复用上次结果 |
| P2 | GPU 加速 | 支持 NVIDIA GPU 加速 OCR，三级策略：强制CPU / 强制GPU / 自动检测 |
| P3 | 文件 I/O 可控 | 截图和 OCR 结果默认不保存到磁盘，可通过 GUI 开关启用 |

### 2.3 界面功能

| 编号 | 功能 | 描述 |
|------|------|------|
| U1 | GUI 主界面 | tkinter 界面，包含状态栏、扫描/OCR/匹配三组配置面板、日志区、操作按钮 |
| U2 | ROI 交互选择 | 全屏半透明覆盖层，鼠标拖拽选取识别区域，支持记忆和复用 |
| U3 | ROI 边框可视化 | 扫描期间在屏幕上显示红色矩形边框标识 ROI 区域 |
| U4 | 实时日志 | 深色主题日志面板，按级别着色（INFO绿/WARNING黄/ERROR红/DEBUG蓝） |
| U5 | 系统托盘 | 雷达扫描风格托盘图标，关闭窗口时最小化到托盘，左键显示/隐藏，右键菜单退出 |
| U6 | 全局热键 | Ctrl+Alt+1 开始扫描 / Ctrl+Alt+2 停止扫描，全局生效无需窗口焦点 |
| U7 | 配置编辑器 | 内置 YAML 编辑器，支持语法高亮、行号、格式验证，保存后自动重载 |
| U8 | 关键词编辑器 | GUI 内嵌文本编辑器，可直接编辑关键词文件 |
| U9 | 内存监控 | 状态栏实时显示进程内存占用（每 5 秒更新） |
| U10 | CLI 模式 | 命令行界面，支持位置参数和交互式输入两种模式 |

### 2.4 配置管理

| 编号 | 功能 | 描述 |
|------|------|------|
| C1 | 双文件配置 | 业务配置存 config.yaml，窗口状态存 gui_state.json |
| C2 | 实时生效 | GUI 参数变更时立即写入 config.yaml 并生效 |
| C3 | 配置重置 | 一键恢复所有配置到默认值 |
| C4 | 脏标记优化 | Config 单例维护 dirty flag，扫描服务仅在配置变更时刷新缓存 |

### 2.5 关键词文件格式

```
用户名关键词 提示词（空白分隔）
用户名关键词:提示词（冒号分隔，兼容格式）
纯关键词（无提示词）
```

### 2.6 浮窗布局

```
┌─────────────────────────────────────────────────────┐
│  [左栏：累积匹配历史]     │  [右栏：当前 OCR 结果]   │
│  关键词1  提示词1（红色）  │  OCR行1（红=匹配）       │
│  关键词2  提示词2（红色）  │  OCR行2（绿=未匹配）     │
│                           │  OCR行3（绿=未匹配）      │
└─────────────────────────────────────────────────────┘
半透明黑色背景，文字带阴影，Microsoft YaHei 粗体
位置可选：居中 / 顶部 / 底部
显示时长 1-10 秒后自动隐藏
```

# 第二部分：new_version PRD

## 1. 产品定位

**产品名称**：屏幕扫描OCR识别系统（Pipeline 版本）

**核心价值**：与主版本相同——游戏匹配期间实时 OCR 识别并提醒标记玩家。架构上采用流水线设计，精简功能集，专注性能和体验。

**目标用户**：同主版本。

## 2. 功能清单

### 2.1 核心功能

| 编号 | 功能 | 描述 |
|------|------|------|
| F1 | 定时屏幕截图 | mss 独占截图（无 PIL fallback），线程安全（thread-local context） |
| F2 | OCR 文字识别 | 仅 PaddleOCR 单引擎，懒加载单例，禁用文档方向检测以提速 |
| F3 | 关键词匹配 | 双层匹配：Aho-Corasick 精确子串匹配（O(T)）+ 比例匹配回退（容忍 OCR 误识别），阈值可调 50%-100% |
| F4 | 浮窗提醒 | 持久透明浮窗，双栏：左侧累积匹配历史 + 右侧当前 OCR 结果 |
| F5 | 音效提醒 | C 大三和弦（C5+E5+G5），350ms 带渐入渐出，内存合成 WAV |

### 2.2 性能优化功能

| 编号 | 功能 | 描述 |
|------|------|------|
| P1 | 帧差检测 | 160x120 灰度 MSE 比较，阈值可配置（GUI 滑动条），画面无变化时跳过 OCR |
| P2 | GPU 加速 | 单开关控制（开/关），无三级策略 |
| P3 | 零文件 I/O | 完全无磁盘写入，无截图/结果保存功能 |

### 2.3 界面功能

| 编号 | 功能 | 描述 |
|------|------|------|
| U1 | GUI 主界面 | tkinter 界面，860x680，紧凑单屏布局 |
| U2 | ROI 交互选择 | 全屏半透明覆盖层，鼠标拖拽选取 |
| U3 | ROI 预设管理 | 支持命名保存/切换多组 ROI 预设 |
| U4 | ROI 边框可视化 | 扫描期间红色边框标识 ROI 区域 |
| U5 | 实时日志 | 深色主题，按级别着色，最大 2000 行 |
| U6 | 系统托盘 | 托盘图标，最小化到托盘 |
| U7 | 全局热键 | Ctrl+Alt+1/2 开始/停止 |
| U8 | 关键词编辑器 | GUI 内嵌文本编辑器 |
| U9 | 帧差阈值调节 | GUI 滑动条实时调节帧差检测灵敏度（0-50） |
| U10 | 语言切换 | 下拉菜单选择 OCR 语言（中/英/日/韩） |
| U11 | 清除匹配记录 | 按钮一键清除当前会话累积的匹配历史 |
| U12 | 内存监控 | 状态栏实时内存占用 |
| U13 | CLI 模式 | 精简命令行界面，输出格式：`[#N] OCR: X行, 匹配: Y, 耗时: Z` |

### 2.4 配置管理

| 编号 | 功能 | 描述 |
|------|------|------|
| C1 | 精简 YAML | 仅保留必要配置项，无 performance/cleanup 分组 |
| C2 | 实时生效 | GUI 参数变更即时保存 |
| C3 | 配置重置 | 恢复默认值 |

### 2.5 浮窗布局

```
┌───────────────────────────────────────────────────────┐
│  [左栏：累积匹配历史]       │  [右栏：当前 OCR 结果]   │
│  关键词1 提示词1（红色）     │  OCR行1（红=匹配）       │
│  关键词2 提示词2（红色）     │  OCR行2（绿=未匹配）     │
│  (按字母排序)               │  OCR行3（绿=未匹配）     │
│  无匹配时："暂无匹配"（灰色）│  无结果时："暂无识别结果" │
└───────────────────────────────────────────────────────┘
透明背景，文字带阴影，Microsoft YaHei 粗体
鼠标穿透（Windows API WS_EX_TRANSPARENT）
C 大三和弦音效提示新匹配
```

# 第三部分：产品经理审查意见

## 审查方法

以产品经理视角，从以下维度对两个版本进行对比审查：
- 用户价值与场景覆盖
- 功能完整性与一致性
- 用户体验与交互设计
- 产品维护性与迭代效率
- 风险与遗漏

---

## 1. 功能对比矩阵

| 维度 | 主版本 | new_version | 审查意见 |
|------|--------|-------------|----------|
| OCR 引擎 | PaddleOCR + EasyOCR | 仅 PaddleOCR | new_version 砍掉 EasyOCR 是合理的。EasyOCR 在中文场景下准确率不如 PaddleOCR，双引擎增加维护成本但无明显用户价值。**建议主版本也考虑移除 EasyOCR**。 |
| 匹配算法 | 子串 + 比例匹配 | Aho-Corasick + 比例匹配 | 两个版本均支持比例匹配。new_version 采用双层策略：先 Aho-Corasick 精确匹配，未命中时回退比例匹配，兼顾性能和容错。 |
| 文件保存 | 可选开关 | 无 | new_version 完全去除文件保存。**问题：用户如何排查 OCR 误识别？** 无法回溯某次扫描的截图和识别结果，会增加调试难度。建议保留 debug 级别的可选保存。 |
| 音效 | 1000Hz 蜂鸣 200ms | C 大三和弦 350ms | new_version 音效体验明显更好。**建议主版本升级音效**，简单蜂鸣在游戏环境中容易与系统提示音混淆。 |
| 帧差阈值 GUI | 仅 config.yaml | GUI 滑动条 | **new_version 更好**。帧差阈值是高频调节项（不同游戏/场景需要不同值），应暴露在 GUI 中。建议主版本也加入此控件。 |
| 语言切换 GUI | 仅 config.yaml | 下拉菜单 | 同上，new_version 更友好。但实际使用中语言几乎不会变（始终是中文），优先级低。 |
| 配置编辑器 | 内置 YAML 编辑器 | 无 | **主版本优势**。高级用户可以直接编辑所有配置项。new_version 缺少此入口，如需调整未暴露在 GUI 中的参数（如 roi_padding），必须手动编辑文件。 |
| 清除匹配记录 | 无独立按钮 | 有按钮 | **new_version 更好**。主版本只能通过重新开始扫描来清除匹配历史，操作路径过长。 |
| ROI 预设 | 有 | 有 | 两者均支持，new_version 实现更完整（下拉选择+保存按钮）。 |

## 2. 用户体验审查

### 2.1 首次使用流程

**主版本问题**：
- 打开 GUI 后控件较多，新用户可能不知道先调什么。缺少引导或默认推荐值说明。
- ROI 选择的操作提示仅出现在日志区（容易被忽略），应有更醒目的视觉引导。

**new_version 问题**：
- 同样缺少新手引导。
- 但控件更少、布局更紧凑，认知负担较低。

**建议**：两个版本都应在首次启动时显示简短操作提示（如 tooltip 或首次弹窗）。

### 2.2 扫描过程中的反馈

**主版本**：
- 状态栏信息充足（状态/次数/时间/内存），但日志刷新过快时难以阅读关键信息。
- 帧差跳过时仅日志 debug 级别输出，用户在 INFO 级别下看不到"已跳过"的反馈，可能误以为程序卡住。

**new_version**：
- CLI 输出格式优秀：`[#N] OCR: 跳过(无变化), 匹配: 0, 耗时: 0.012s`，一行包含所有关键信息。
- GUI 日志同样采用此格式，信噪比更高。

**建议**：主版本的 GUI 日志应参考 new_version 的单行摘要格式，减少信息冗余。

### 2.3 浮窗交互

**两个版本共同问题**：
- 浮窗在扫描间隔内反复出现/隐藏（每次扫描都触发），如果扫描间隔 < 显示时长，浮窗会一直闪烁。
- **建议**：当匹配结果与上次相同时，应保持浮窗显示而非重新触发渐显动画。

**主版本特有问题**：
- 浮窗的多种布局模式（单列/双列/三列）由数据结构自动选择，用户无法控制，可能导致布局跳变。

**new_version 优势**：
- 固定双栏布局，视觉稳定。
- 匹配历史按字母排序，便于快速扫视。
- "暂无匹配"/"暂无识别结果" 占位文本避免空窗口。

### 2.4 匹配结果可操作性

**两个版本共同缺失**：
- 匹配到关键词后，用户只能"看到"提醒，无法执行任何操作（如复制关键词、标记已处理、跳转到相关信息）。
- 浮窗鼠标穿透设计是正确的（避免遮挡游戏操作），但也意味着用户无法与匹配结果交互。
- **当前阶段可接受**，因为核心场景是"提醒"而非"操作"。未来可考虑在主窗口中增加匹配历史列表。

## 3. 产品策略审查

### 3.1 两个版本的定位冲突

**核心问题**：两个版本解决同一问题、面向同一用户，但同时维护两套代码。

**建议**：
- 应明确一个版本为**主力版本**，另一个为**归档/实验版本**。
- 从技术质量看，new_version 架构更清晰（pipeline 模式、关注点分离），适合作为未来主力。
- 从功能完整度看，主版本功能更丰富（双引擎、比例匹配、配置编辑器）。
- **推荐路径**：以 new_version 架构为基础，将主版本的差异化功能（比例匹配、配置编辑器）移植过去，最终收敛为一个版本。

### 3.2 关键功能缺失

以下功能两个版本均未覆盖，按优先级排列：

| 优先级 | 功能 | 理由 |
|--------|------|------|
| P1 | 匹配历史导出/查看 | 一局游戏结束后，用户可能想回顾本局遇到了哪些标记玩家。当前会话结束即丢失。 |
| P2 | 多关键词文件切换 | 不同游戏/场景可能有不同的黑名单。当前只能手动切换文件路径。 |
| P3 | 关键词分组/分类 | 如"黑名单"和"好友名单"用不同颜色提醒。当前所有匹配等同处理。 |
| P4 | 自动更新关键词 | 从远端（如共享文档/API）自动同步关键词列表。 |

### 3.3 风险评估

| 风险 | 影响 | 当前缓解 | 建议 |
|------|------|----------|------|
| OCR 误识别导致漏报 | 高 | 比例匹配（两个版本均支持） | 当前方案可接受，阈值可通过 GUI 调节 |
| OCR 误识别导致误报 | 低 | 提示词+OCR 原文双列显示 | 当前方案可接受 |
| 游戏反作弊检测 | 中 | 无 | 截图方式（mss/GDI）一般不被检测，keyboard 全局钩子有风险，建议文档说明 |
| 管理员权限依赖 | 中 | keyboard 库需管理员权限 | 应提供无热键的降级模式说明 |
| 长时间运行内存泄漏 | 低 | 内存监控+gc.collect | 当前方案可接受 |

## 4. 综合评分

| 维度 | 主版本 | new_version | 说明 |
|------|--------|-------------|------|
| 功能完整度 | 9/10 | 8/10 | 主版本仍多出双引擎和配置编辑器 |
| 架构质量 | 7/10 | 9/10 | new_version pipeline 架构更清晰、可测试、可维护 |
| 用户体验 | 7/10 | 8/10 | new_version 界面更紧凑、日志格式更优、音效更好 |
| 性能 | 8/10 | 9/10 | new_version Aho-Corasick 优先+比例回退、零 I/O、无冗余转换 |
| 可维护性 | 6/10 | 9/10 | 主版本 app.py 1160 行单文件，new_version 按阶段拆分 |
| 部署简便性 | 8/10 | 7/10 | new_version 多依赖 pyahocorasick（需编译），主版本纯 Python |

## 5. 最终建议

### 短期（当前迭代）

1. **主版本**：将 GUI 日志格式改为 new_version 的单行摘要格式；升级音效为和弦；增加帧差阈值 GUI 控件；增加"清除匹配记录"按钮。
2. **new_version**：~~补充比例匹配功能~~（已完成）；增加可选的 debug 截图保存。

### 中期（下一迭代）

3. 选定 new_version 为主力架构，将主版本的配置编辑器移植过去。
4. 归档主版本，停止双线开发。

### 长期

5. 增加匹配历史持久化和查看功能。
6. 支持关键词分组和多配色方案。
